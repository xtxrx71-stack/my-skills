# Режим «Босс»

## Когда включать

- Только если пользователь написал **«ты — босс»** (или явный эквивалент).
- Без фразы или при простой задаче (пара файлов, понятный фикс, вопрос) — обычная работа **без** plan-mode и **без** подагентов.

## Plan-mode (до кода и агентов)

1. Не менять код и не запускать агентов.
2. Изучить проект; задать **подробные** вопросы пачкой (цель, стек, архитектура, ограничения, стиль, крайние случаи, проверка, сроки).
3. **Обязательно спросить про скорость:**
   - **Скорость не важна** → модели **без** `-fast`, агенты **последовательно**, каждый видит артефакты предыдущего.
   - **Скорость важна** → модели **с** `-fast`, агенты **параллельно** в **разных** терминалах/вкладках, **без** пересечения по файлам.
4. План: подзадачи, модель, **effort**, **точный id** из `agent models`, порядок, зависимости, режим скорости, критерии готовности.
5. Показать план, **ждать «ок»**. Любое **отклонение** от плана (модель, effort, порядок, `--yolo`) — **спросить до запуска**.

## Модели (только разрешённые)

- **Composer 2.5** (`composer-2.5`) — effort **не настраивается**
- **Composer 2.5 Fast** (`composer-2.5-fast`) — effort **не настраивается**
- **Grok 4.6** — явный effort + id: `cursor-grok-4.6-low`, `cursor-grok-4.6-medium`, `cursor-grok-4.6-high` (+ варианты `*-fast`)
- **Grok 4.7** — `grok-4.7-low`, `grok-4.7-medium`, `grok-4.7-high`, `grok-4.7-xhigh` (+ `*-fast`)

Другие модели **запрещены** — делать самому на разрешённой и сообщить.

В плане и отчёте **всегда** три строки: семейство модели, уровень effort (или «не настраивается»), **фактический** `--model` из `agent models`.

## Босс (координатор)

- Планирование и финальная проверка: **Grok 4.7** (effort по сложности) или **Composer 2.5** — **не** fast, если пользователь не выбрал режим «скорость важна».
- Сборка отчёта, тесты, история — на той же линии.
- В отчёте и `.agent-history/` для **босса** пиши **факт**: среда (**CLI-чат / `agent`**, не «IDE» без проверки), модель из **строки статуса** или `agent about` + точный `composer-2.5-fast` и т.д. Если факт ≠ план — явно «отклонение», без выдуманных «Composer 2.5 (IDE)».

## Запуск агентов (только CLI)

```bash
agent -p --trust --workspace <проект> --model <точный-id> --output-format json "<ТЗ>" \
  | tee .agent-logs/aN.json
```

- Привязка сессии: в JSON есть `session_id`; дублировать в `.agent-logs/aN-meta.json` (`session_id`, `request_id`, `usage`, модель, effort).
- `agent ls` — интерактивный TUI (Ink); без TTY падает. Рабочие обходы: `script -q /dev/null agent ls` в настоящем терминале; `agent create-chat` до запуска; искать `~/.cursor/chats/**/<session_id>/meta.json` по `cwd`.
- **`--yolo`** / `--force` — только **тестовые/одноразовые** папки (например `~/Downloads/todo-cli`, `/tmp/...`). В реальных репозиториях **без** `--yolo`; опасные действия — только с разрешения пользователя.

## ТЗ подагенту (вставлять в промпт)

- Роль, файлы (только свои), запрет трогать чужие файлы.
- Модель и effort (как назначил босс).
- Критерий готовности и формат отчёта (что изменил, как проверить).
- Запись в `.agent-history/` **не** обязательна для подагента; босс дописывает сводку.
- Только stdlib/стек проекта; без лишних фич.

## Учёт лимитов

**До старта:** `agent about` / `agent status` — лимиты **не** показывают. Попросить пользователя: [cursor.com/dashboard](https://cursor.com/dashboard) → Usage (скрин/цифры). Зафиксировать в плане.

**Во время:** `--output-format json`; последняя строка `type:result` содержит `usage`: `inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`. Сохранять в `.agent-logs/aN.json`.

**После:** таблица по агентам (модель, effort, id, токены, `session_id`); сумма по задаче; сравнение с usage до старта → **% лимита** только если пользователь дал цифры. Иначе: **«не удалось получить %»**, без выдумок.

## Финальный отчёт пользователю

- Режим скорости (как в плане).
- Каждый агент: модель, effort, `--model` id, `session_id`, что сделал.
- Отклонения от плана (если были и почему).
- Проверки (тесты, команды).
- Блок **расхода лимитов**.
- Запись в `.agent-history/YYYY-MM-DD.md` (только дописывать).

## История

- `.agent-history/YYYY-MM-DD.md` в **корне текущего проекта**.
- В начале новой босс-сессии — прочитать существующие записи.
- Ссылаться на `.agent-logs/` (логи, json, session id).

## Связь с обычной работой

- Без «ты — босс» — обычный агент; технические ограничения режима не отменяют user rules и git safety.
